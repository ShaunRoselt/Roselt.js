Shell components

Shell components are regular components placed outside the routed page root.

Use shell components for shared UI such as headers, footers, sidebars, legal notices, or global navigation. They use the same component system as everything else in Roselt.js.

Place them around the routed page

<site-header></site-header>
<main class="app-shell">
  <roselt page="home" navigate></roselt>
</main>
<site-footer></site-footer>

Roselt.js sees <site-header>, loads components/site-header.js, and leaves that element mounted while the page root navigates between routes.

Use light DOM when the shell should share global styles

Most shell components want access to the main stylesheet, so it is common to set this.shadow = false and render normal light DOM markup.

Roselt.defineComponent(function () {
  this.shadow = false;

  this.render = () => `
    <header class="site-header">
      <a href="?page=home">My app</a>
    </header>
  `;
});

What belongs in the shell

Persistent layout chrome

Use shell components for headers, footers, sidebars, toolbars, and any other UI that should not remount on each route.

Global controls

Menus, search overlays, theme toggles, and account menus often fit naturally in shell components because they live above the routed page.

Shared composition

Because shell components use the same component API, you can move markup between shell and page contexts without learning a second system.

Resolution rules

Reference How Roselt.js resolves it
<site-header> Resolved to components/site-header.js.
<admin-sidebar> Resolved to components/admin-sidebar.js.
Hyphen requirement Component filenames and tag names must include a hyphen because they use the browser custom element model.
