Project structure

Roselt.js reads your directory layout as application structure.

The framework is intentionally opinionated here. Instead of maintaining a separate route registry for common cases, you usually let Roselt.js resolve requested pages and components directly from the default folders.

Default layout

index.html
pages/
  home.html
  home.js
  docs/getting-started.html
components/
  site-header.js
  site-footer.js
  ui-button.js

Directory roles

Directory What belongs there
pages/ Routeable HTML files, optional page modules, and optional same-name CSS files.
components/ Component files loaded when their tag names appear in the shell or the rendered page. This includes reusable controls and shell pieces like headers, footers, and sidebars.

Nested pages are just nested folders

If the URL requests ?page=blog/post, Roselt.js looks for pages/blog/post.html and pages/blog/post.js.

No extra route object required

File-based page resolution is the default. You only need explicit routes when you want custom paths, pathname parameters, extra route metadata, or custom file locations.

Shell components are just components

If a component should stay mounted for the whole app, place the tag around the routed page root in index.html. If it only belongs to one route, place the tag inside that page file.

<site-header></site-header>
<main class="app-shell">
  <roselt page="home" navigate></roselt>
</main>
<site-footer></site-footer>
